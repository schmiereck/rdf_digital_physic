# Phase 249 Sub-Goal A: Construct Non-Additive LUT Variants for 3D FCC LGCA

## Context
In iter_248, we discovered that ALL "gliders" on the 3D FCC lattice are non-interacting composites of single-bit particles. The root cause is that the O_h-symmetric LUT (e.g. LUT-08) is **additive at weight-2**: when two bits occupy the same cell, the LUT output is the independent superposition of the two weight-1 transpositions. Bits from different velocity cycles never interact. We need to construct LUTs where weight-2 entries are deliberately **non-additive** — redirecting output bits across velocity cycles — to test whether genuine multi-bit coherent gliders can emerge.

## Main Task: Construct Non-Additive LUT Variants

### Step 1: Analyze the weight-1 structure of LUT-08
Read `src/experiment_248_fundamental_spectrum.py` and `archive/iter_248/results/fundamental_spectrum.json` to understand the LUT-08 weight-1 cycles. The 6 period-2 transposition pairs are:
- ch0↔ch3, ch1↔ch2, ch4↔ch7, ch5↔ch6, ch8↔ch11, ch9↔ch10

### Step 2: Enumerate weight-2 channel pairs and group into O_h orbits
There are C(12,2)=66 possible weight-2 pairs {(ch_i, ch_j)}. Group them by their geometric relationship on the FCC cuboctahedron:
- **Same-cycle pairs** (within a transposition): e.g., (0,3), (1,2), (5,6), etc. — these are "adjacent" in the transposition cycle.
- **Cross-cycle pairs** (from different transposition cycles): e.g., (0,5), (3,6), etc.
- **Antipodal pairs** (opposite on the cuboctahedron)

Group all 66 pairs into O_h orbits. Use the O_h permutation machinery from `src/search_3d_gliders.py`.

### Step 3: Determine the additive (default) LUT-08 output for each weight-2 input
For each weight-2 input state s = (1<<ch_i) | (1<<ch_j), the additive LUT-08 output is:
  lut[s] = lut[(1<<ch_i)] | lut[(1<<ch_j)]
This is the independent superposition of the two weight-1 transpositions.

### Step 4: Design three non-additive interaction types

**LUT-INT-EXCHANGE:** For cross-cycle weight-2 pairs, swap one output bit with a bit from another transposition pair. Example: if input has bits in ch0 and ch5, the additive output would place bits in ch3 and ch6 (since 0→3, 5→6). Instead, redirect ch0's output to ch1 (belongs to cycle {1,2}) and ch5's output stays at ch6. This creates cross-cycle leakage.

**LUT-INT-BINDING:** For cross-cycle weight-2 pairs, redirect both output bits into the SAME velocity cycle. Example: if input has ch0 and ch5, redirect outputs so both bits go into the {0,3} cycle (both go to ch0 or ch3). This creates co-propagation tendency.

**LUT-INT-SCATTERING:** For cross-cycle weight-2 pairs, redirect both output bits into the stationary cycle {8,11}. This creates energy-like dissipation at collision sites, potentially trapping bits.

### Step 5: Close modifications under full O_h group
For each non-additive modification, apply all 48 O_h permutations to propagate it equivariantly across all weight-2 states in the same orbit. Use the machinery from `src/search_3d_gliders.py` (precompute_perm_action, compute_orbits, etc.).

### Step 6: Verify each variant
For each non-additive LUT variant, programmatically verify:
1. **Bijection:** len(np.unique(lut)) == 4096
2. **Bit conservation:** hamming(s) == hamming(lut[s]) for all s
3. **O_h symmetry:** lut[sigma_g(s)] == sigma_g(lut[s]) for all g in O_h
4. If any variant fails verification, document the failure and iterate.

### Step 7: Save verified LUTs
Save each verified LUT variant to `src/nonadditive_lut_*.npy` files. Also save a JSON metadata file describing exactly which weight-2 pairs were modified and what the original vs modified outputs were.

### Step 8: Build coherence testing module
Create `src/coherence_testing.py` that implements the three-test protocol from iter_248:
- Test A (decomposition): Run each bit independently; check if combined trajectory matches multi-bit trajectory.
- Test B (bit-removal): Remove one bit from initial conditions; check if remaining pattern is destabilized.
- Test C (collision interaction): Collide candidate with a test particle; check for non-trivial outcome.
