The goal is to breed a new generation of rules from the top performers of iter_159 to see if we can improve the `late_displacement / (1 + final_bit_count)` fitness score.

**Background:**
- In `iter_159`, we ran an initial evolutionary search (Gen-1) with a new composite fitness metric and found a promising founder rule.
- The fitness is calculated as `displacement in steps 1200-2000 / (1 + final_bit_count)`.
- The simulation runs for 2000 steps on a 128x128 grid, seeded with a 16x16 block of 50% random noise.

**Task Steps:**
1.  **Load Gen-1:** Read the population data from `archive/iter_159/results/population/`. This includes 100 JSON files, each containing a rule and its fitness score.
2.  **Selection:** Identify the top 10 rules from Gen-1 based on their fitness scores. These will be the "elite" parents.
3.  **Breeding (Gen-2):** Create a new population of 100 rules for Gen-2.
    - The top 2 elite rules (the champion and runner-up) are carried over directly to the next generation (elitism).
    - The remaining 98 rules are generated by randomly selecting two parents from the elite pool and performing a crossover operation.
    - Apply a small mutation to each new rule after crossover.
4.  **Evaluation:** Evaluate the fitness of each of the 100 rules in the new Gen-2 population using the **exact same simulation and fitness function** as in `iter_159`.
5.  **Save Results:**
    - Save the new Gen-2 population and their fitness scores to `archive/iter_163/results/population/`.
    - Create a `summary.json` file in `archive/iter_163/results/` containing:
        - `gen1_mean_fitness`
        - `gen2_mean_fitness`
        - `gen1_champion_fitness`
        - `gen2_champion_fitness`
        - `fitness_improvement_pct` (mean vs mean)
6.  **Report:** Complete the final YAML block with the key metrics from `summary.json`. The `experimenter_view` should comment on whether the evolutionary process appears to be working.

The core logic for selection, breeding, and evaluation should be adapted from the scripts used in previous evolutionary runs. The key is to build upon the results of `iter_159`.
