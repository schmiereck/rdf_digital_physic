## How the Script Works for Sub-Light Speed Glider Search

### Architecture Overview

The script runs a **generational evolutionary algorithm** over a population of 100 hexagonal cellular automaton rules, searching for rules that produce stable v<c gliders (moving objects that preserve their structure and direction) from an L-tromino 3-bit seed.

### Key Components

1. **Chromosome representation** — Each rule is a 128-bit gene vector. The rule encodes a hexagonal (7-neighbor) CA where 7 of the 8 neighbors define a 7-bit index (0–127), and the output bit (birth/survive) is at bit 6. The chromosome stores just the 128 output bits.

2. **LUT (Look-Up Table) encoding** — `rule_dict_to_lut()` converts the sparse `rule_dict` into a 128-entry lookup table mapping each hex-neighbourhood state to a single output bit.

3. **Simulation** — The L-tromino seed `{(63,63), (64,63), (64,64)}` is placed on a 128×128 toroidal grid. The grid is stepped forward for `STEPS=500` iterations, and at each step the centre-of-mass (COM) and live-cell count ("bits") are recorded.

4. **`DisplacementConsistencyFitness`** — This is the **validated fitness function**. It divides the 500-step history into 5 equal time windows, computes a velocity vector (ΔCOM) per window, then rewards:
   - **High mean displacement** (true gliders travel far)
   - **Low std dev of velocity magnitudes** (the motion is *consistent* — not a drifter)
   - **Bit conservation** via a "leaky" score that gives partial credit even when bits are lost

The formula:
```
fitness = mean_velocity_magnitude / (1 + std_dev_velocity_magnitudes) × conservation_score
```

5. **Evolution loop** — Each generation: keep the top-10 elite rules, mutate the rest via random-swap (1 swap per child at `mutation_rate=0.01`), evaluate, and track the global champion.

## Complete Explanation

### How the Evolutionary Search Finds v<c Gliders

The script runs a **generational (1+1)-evolutionary algorithm** to discover hexagonal cellular automaton rules that make the L-tromino seed (`{(63,63), (64,63), (64,64)}`) travel as a **v<c glider** — a coherent object that moves at constant velocity while preserving its structure.

### Architecture (step by step)

#### 1. Rule Representation
Each hexagonal CA rule is encoded as a **128-entry look-up table (LUT)**. A hexagonal neighborhood has 7 neighbors, giving 2⁷ = 128 possible neighbor configurations. The LUT maps each configuration to a 0/1 output (cell dies or lives). The chromosome is a 128-bit binary vector storing these output values.

#### 2. Initialization
100 random **C₂-symmetric rules** are generated (rotating 180° leaves the rule unchanged, a physical constraint that keeps objects from spiraling away).

#### 3. Simulation (`simulate_with_history`)
For each rule:
- The L-tromino 3-cell seed is placed on a 128×128 toroidal grid
- The grid is evolved for 500 steps
- At each step, the **centre of mass (COM)** and **bit count** (live cell count) are recorded
- This produces a history of 501 data points

#### 4. Fitness Evaluation (`DisplacementConsistencyFitness`)

This is the core of the glider search. The fitness function divides the 500-step history into **5 equal time windows** and computes:

| Component | Formula | Purpose |
|-----------|---------|---------|
| Per-window velocity | ΔCOM per window | Measures directional motion |
| Mean velocity vector | mean of per-window (Δx, Δy) | Rewards consistent directional drift |
| Mean velocity magnitude | √(meanₓ² + mean_y²) | The numerator of the fitness |
| Std dev of magnitudes | σ of per-window \|v\| | Penalizes inconsistent (drifter) motion |
| Conservation score | mean of per-step bit-ratio | Enforces mass preservation |

**The core formula:**
```
base_fitness = mean_velocity_magnitude / (1 + std_dev_velocity_magnitudes)
final_fitness = base_fitness × conservation_score
```

- A **true v<c glider** has near-zero std dev (identical velocity in every window) → denominator ≈ 1 → high fitness
- A **drifter** has wildly varying velocities → large denominator → low fitness (even if mean displacement is high)
- A **stationary object** has near-zero mean velocity → fitness ≈ 0

#### 5. Selection & Mutation
- **Tournament selection**: keep the top 10 rules (elite)
- **Swap mutation**: each child gets 1 random bit swap per generation (0.01 × 128 ≈ 1 swap)
- Offspring fill the remaining 90 slots in the next generation

#### 6. Output
- `champion_rule.json`: The best rule's full rule dict, chromosome, and all experiment metadata
- `evolution_summary.csv`: Per-generation best and mean fitness (now written via the `csv` module)
