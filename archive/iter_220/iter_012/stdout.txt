### 1. `_rotate_c2(state: int) -> int`

```python
def _rotate_c2(state: int) -> int:
    return _rotate60(_rotate60(_rotate60(state)))
```

This rotates a hex-neighbourhood state 180° (C2 rotation = two 60° rotations = 3 × 60°). With the 7-bit MSB encoding (bit6=center, bits 5–0 for E,SE,SW,W,NW,NE), rotating 180° maps:

| Position | → | New Position |
|----------|---|--------------|
| NE       | → | SW           |
| E        | → | W            |
| SE       | → | NW           |
| Center   | → | Center       |

So a 180° rotation of state `0b1001011` = `(c,E,SE,SW,W,nw,NE)` becomes `(c,NE,NW,SE,W,E,SW)`.

### 2. `_try_build_c2_rule(pairs: list) -> dict | None`

```python
def _try_build_c2_rule(pairs: list) -> dict | None:
    rule: dict = {}
    for a, b in pairs:
        rot_a, rot_b = _rotate_c2(a), _rotate_c2(b)
        for src, dst in [(a, b), (b, a), (rot_a, rot_b), (rot_b, rot_a)]:
            if src in rule:
                if rule[src] != dst:
                    return None
            else:
                rule[src] = dst
    return rule
```

This is the **consistency checker**: for each generator pair `(a→b)`, it also enforces `(b→a)` (symmetry) and `(rot_a→rot_b)`, `(rot_b→rot_a)` (C2 symmetry). If any assignment contradicts a previous one, it returns `None`. Otherwise it returns a full 128-entry rule dict.

## How to Write a C2-Preserving Mutation Function

There are **three established approaches** used across the codebase. Here's the design:

### Approach 1: Pair-Add / Pair-Remove (Used in `run_v_less_than_c_search.py`)

The key insight: C2 rules are stored as full 128-entry dicts, but they are fully determined by a small set of **generator pairs**. A mutation operates on this pair list, then rebuilds the rule:

```python
def _extract_base_pairs(rule: dict) -> list[tuple[int, int]]:
    """Extract one representative (a,b) per C2-orbit from a rule dict."""
    visited: set[int] = set()
    pairs: list[tuple[int, int]] = []
    for a, b in rule.items():
        if a not in visited and b not in visited:
            pairs.append((int(a), int(b)))
            visited.add(int(a))
            visited.add(int(b))
            ra, rb = _rotate_c2(int(a)), _rotate_c2(int(b))
            visited.add(ra)
            visited.add(rb)
    return pairs

def mutate_c2_rule(rule: dict, rng: random.Random,
                   n_add: int = 1, n_remove: int = 1) -> dict:
    """C2-preserving mutation: add/remove generator pairs, then rebuild."""
    pairs = _extract_base_pairs(rule)

    # Remove existing pairs at random
    for _ in range(n_remove):
        if pairs:
            pairs.pop(rng.randrange(len(pairs)))

    # Add new random pairs
    for _ in range(n_add):
        a = rng.randint(1, 127)
        b = rng.randint(1, 127)
        while b == a:
            b = rng.randint(1, 127)
        pairs.append((a, b))

    new_rule = _try_build_c2_rule(pairs)
    if new_rule is None:
        # Fallback: inconsistent pairs → start fresh
        return generate_random_c2_rule(rng)
    return new_rule
```

**Why this preserves C2:** The mutation only manipulates generator pairs. The rebuild step via `_try_build_c2_rule` guarantees the full 128-entry rule respects C2. If the random additions are inconsistent, we fall back to a clean random C2 rule.

### Approach 2: Single-Pair Replacement (Used in `evolve_reboot_gen3.py`)

Replace one generator pair with another, avoiding state-space collisions:

```python
def mutate_one_pair(pairs: list, rng: random.Random) -> list:
    """Replace exactly one pair with a fresh valid pair."""
    pairs = list(pairs)
    idx = rng.randrange(len(pairs))
    pairs[idx] = (rng.randint(1,127), rng.randint(1,127))
    # Retry until no state collision with remaining pairs
    return pairs
```

This requires careful collision avoidance — the replacement pair must not share any state with its C2 orbit against the other pairs.

### Approach 3: Probabilistic Keep + Add (Used in `run_iter_171_evo.py`)

```python
def mutate_rule(parent_rule: dict, rng: random.Random,
                drop_rate: float = 0.4) -> dict:
    """Child = kept subset of parent pairs + fresh random pairs."""
    parent_pairs = extract_base_pairs(parent_rule)
    for _ in range(2000):
        kept  = [p for p in parent_pairs if rng.random() > drop_rate]
        n_new = rng.randint(1, 4)
        new_p = kept[:]
        for _ in range(n_new):
            a = rng.randint(1, 127)
            b = rng.randint(1, 127)
            while b == a:
                b = rng.randint(1, 127)
            new_p.append((a, b))
        if not new_p:
            continue
        rule = _try_build_c2_rule(new_p)
        if rule is not None:
            return rule
    return generate_random_c2_rule(rng)
```

### The Golden Rule for C2-Mutation

> **Never mutate the 128-entry lookup table directly.** Instead, always operate on the *generator pair list*, then use `_try_build_c2_rule()` to reconstruct the full rule. This guarantees C2 symmetry by construction, and the `_try_build_c2_rule` consistency check catches all invalid mutations.

The mutation budget is always a *swap* — remove N pairs, add N pairs — which keeps the rule's expressiveness (number of generator pairs) roughly constant. The fallback to `generate_random_c2_rule` when `_try_build_c2_rule` returns `None` ensures the mutation always produces a valid child, at the cost of losing the parent's structure in rare cases.
