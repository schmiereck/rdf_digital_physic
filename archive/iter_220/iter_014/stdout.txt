## File 1: `src/new_fitness.py` — `DisplacementConsistencyFitness`

### What it does

This is a **drifter-resistant** fitness function for discovering v<c (sub-light speed) gliders in cellular automata. It defeats a known exploit where objects perform random-walk or oscillating motion to fake high displacement scores.

### Core Formula

```
base_fitness = mean_velocity_magnitude / (1 + std_dev_velocity_magnitudes)
final_fitness = base_fitness * total_conservation_score
```

### How Bit Conservation Is Calculated (`_compute_conservation_score`)

The **"leaky"** conservation scoring is applied per step in the simulation history:

| Condition | Formula |
|-----------|---------|
| `bit_count[i] == initial_bits` | `conservation_factor[i] = 1.0` |
| Otherwise | `conservation_factor[i] = min(bit_count, initial) / max(bit_count, initial)` |

The **total conservation score** is the **mean of all per-step conservation factors**, yielding a value in **[0, 1]**:
- **1.0** = perfect bit conservation throughout
- **0.5** = one step lost half the bits, everything else was fine
- **0.0** = bit count diverged heavily

This is "leaky" because instead of hard-failing on any bit-count change (like `CheckpointFitness`), it applies a **continuous fractional penalty**, preserving the evolutionary gradient.

### Velocity Consistency Calculation

1. Divide `sim_history` into `num_windows` (default: 5) equal-duration windows
2. For each window, find the first and last entries, compute the displacement vector `ΔCOM` → its magnitude
3. Compute the **mean velocity vector** across all windows (directional drift)
4. Compute the **standard deviation of per-window velocity magnitudes**
5. Apply the formula above

A true glider gets **low std_dev** → high fitness. A drifter gets **high std_dev** → heavily penalised.

## File 2: `src/run_vc_search.py` — Evolutionary Search Runner

### Search Configuration

| Parameter | Value | Description |
|-----------|-------|-------------|
| `POPULATION_SIZE` | 100 | Number of random C2-symmetric rules |
| `NUM_GENERATIONS` | 10 | Evolutionary generations |
| `ELITE_FRACTION` | 0.10 | Top 10% advance to next generation |
| `CROSSOVER_RATE` | 0.8 | Two-point crossover probability |
| `MUTATION_RATE` | 0.01 | Per-bit flip probability |
| `LUT_SIZE` | 128 | Rule table size |
| `RNG_SEED` | 200001 | Random seed |
| `GRID_SIZE` | 128 | Simulation grid dimensions |
| `SIMULATION_STEPS` | 200 | Number of CA steps |
| `DENSITY` | 6 | C2 rule generation parameter |
| `SEED_PARTICLE` | `[(0,0), (0,1), (1,1)]` | 3-bit L-tromino |

### Fitness Function Selection

| Flag | Fitness Function | Bit Conservation |
|------|-----------------|------------------|
| (default) | `LeakySubLightFitness` | Continuous fractional penalty (checkpoints at 50, 100, 150) |
| `--strict` | `SubLightFitness` | **Strict** — hard failure on any bit-count change |

### Key Search Flow

1. **Generate initial population** of 100 random C2-symmetric rules
2. **Evaluate** each chromosome → convert to rule_dict → run fitness
3. **Elitism**: select top 10%, breed via crossover + mutation
4. **Track champion** across generations
5. **Output**: `champion_vc_rule.json`, `evolution_log.csv`, `champion_vc_glider.gif`

### Chromosome Encoding

Rules are encoded as 128-bit binary chromosomes:
- Each LUT entry is 7 bits (3 neighbor-count bits + 1 center bit + 3 neighbor-state bits)
- Only the center bit (bit 6) is varied; the rest are fixed per rule index
- `rule_dict_to_chromosome`: extracts center bits from rule dict
- `chromosome_to_rule_dict`: reconstructs rule dict from chromosome, keeping only bits that differ from defaults
