### Core step function (`src/engine.py` lines 117–158)

```python
def step_grid(
    grid: np.ndarray,
    lut: np.ndarray,
    bits_per_cell: int = 1,
) -> np.ndarray:
    """Advance one CA step.

    Accepts either a 3D ``(H, W, N)`` bit-grid or, for ``N == 1``, a 2D
    ``(H, W)`` grid for backward compatibility.  Always returns a 3D
    ``(H, W, N)`` array.
    """
    n = int(bits_per_cell)
    cell = _pack_cell_values(grid, n)
    e = np.roll(cell, -1, axis=0)
    w = np.roll(cell, 1, axis=0)
    ne = np.roll(cell, -1, axis=1)
    sw = np.roll(cell, 1, axis=1)
    se = np.roll(e, 1, axis=1)
    nw = np.roll(w, -1, axis=1)

    if n == 1:
        # Legacy fast path — produces uint8 indices identical to evolution.step_grid.
        state = (
            (cell.astype(np.uint16) << 6)
            | (e.astype(np.uint16) << 5)
            | (se.astype(np.uint16) << 4)
            | (sw.astype(np.uint16) << 3)
            | (w.astype(np.uint16) << 2)
            | (nw.astype(np.uint16) << 1)
            | ne.astype(np.uint16)
        ).astype(np.uint8)
    else:
        dt = _state_dtype(n)
        state = (
            (cell.astype(dt) << (6 * n))
            | (e.astype(dt) << (5 * n))
            | (se.astype(dt) << (4 * n))
            | (sw.astype(dt) << (3 * n))
            | (w.astype(dt) << (2 * n))
            | (nw.astype(dt) << n)
            | ne.astype(dt)
        )
    new_cell = lut[state]
    return _unpack_cell_values(new_cell, n)
```

```python
def _step_grid(grid: np.ndarray, lut: np.ndarray) -> np.ndarray:
    e  = np.roll(grid, -1, axis=0)
    w  = np.roll(grid,  1, axis=0)
    ne = np.roll(grid, -1, axis=1)
    sw = np.roll(grid,  1, axis=1)
    se = np.roll(e,     1, axis=1)
    nw = np.roll(w,    -1, axis=1)
    state = (
        (grid.astype(np.uint16) << 6)
        | (e.astype(np.uint16)  << 5)
        | (se.astype(np.uint16) << 4)
        | (sw.astype(np.uint16) << 3)
        | (w.astype(np.uint16)  << 2)
        | (nw.astype(np.uint16) << 1)
        |  ne.astype(np.uint16)
    ).astype(np.uint8)
    return lut[state]
```

## Why the number of active cells changes

This is a **generalized hexagonal (7-neighbor) cellular automaton** where:

1. **7-bit neighborhood encoding**: Each cell's new state is determined by its own value plus its 6 hexagonal neighbors (E, W, NE, SW, SE, NW), packed into a 7-bit integer index (0–127 for 1-bit cells).

2. **Arbitrary LUT lookup**: The 7-bit index is used to look up the new center cell value from a 128-entry lookup table. This is **not a conservative rule** — the LUT is learned/optimized for motion, not for conservation.

3. **No conservation constraint**: Unlike Conway's Game of Life (where rules like B3/S23 have some emergent conservation properties), this LUT is essentially a **black-box 1-to-1 mapping** from neighborhoods to new center cell values. The mapping is optimized by evolution for displacement (glider velocity), not for conserving the number of active cells.

4. **Consequences**:
   - If a neighborhood maps to `0` (dead), cells die
   - If a neighborhood maps to `1` (alive), new cells are born
   - The balance depends entirely on the specific 128-entry rule table
   - Some rules are **non-conserving** (cell count drifts) — this is actually desirable for glider motion, as gliders must be able to create/die cells at their leading and trailing edges to propagate

5. **Torus wrapping**: `np.roll` means the grid wraps around at the edges, so no cells are lost at boundaries — all changes come purely from the rule.

In short: **the number of active cells changes because the rule LUT is an arbitrary (evolved) mapping from 7-bit neighborhoods to new cell states, not a conserving rule**. This is by design — gliders need to be able to grow and shrink to propagate.
