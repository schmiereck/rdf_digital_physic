### Current Behavior — No Strict Mode Exists

**Short answer:** There is currently **no parameter** to enable strict bit conservation. The current `_compute_conservation_score` method uses a "leaky" continuous penalty approach — it **never returns 0** unless the bit count drops to exactly 0.

### How the Current `_compute_conservation_score` Works

The method applies a per-step fractional penalty:

```
if bit_count == initial_bits:
    factor = 1.0
else:
    factor = min(bit_count, initial_bits) / max(bit_count, initial_bits)
```

For `initial_bits = 3`, this gives:

| bit_count | conservation_factor |
|-----------|-------------------|
| 3 | 1.0 |
| 2 | 2/3 ≈ 0.667 |
| 1 | 1/3 ≈ 0.333 |
| 0 | 0.0 |
| 4 | 3/4 = 0.75 |

The **final** conservation score is the **mean** of all per-step factors. So a single step with `bit_count=2` when `initial=3` would give a factor of 0.667 for that step — the final score is only partially penalised, not hard-zeroed.

### Why This Is Not Strict

With strict bit conservation (hard-fail if bit count ever ≠ initial value), any deviation should yield a fitness of 0.0. But currently:

- **A particle that temporarily gains/loses a bit** still gets partial fitness (e.g., ~0.75-0.9 depending on how many steps deviate).
- **The only way to get 0.0** is if the bit count reaches 0 at some step.
- **The final fitness** is `base_fitness * conservation_score`, so the leaky multiplier only attenuates — it doesn't eliminate.

def _compute_conservation_score(self, sim_history: list[dict[str, Any]]) -> float:
    if not sim_history:

    initial_bits = sim_history[0]["bit_count"]
    if initial_bits == 0:

    conservation_factors: list[float] = []
    for entry in sim_history:
