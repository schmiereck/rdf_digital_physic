### Summary of how windowed velocities are computed:

1. **Window boundaries** (line 286–293): The total simulation steps are divided into `self.num_windows` equal-sized windows. Each window has `steps_per_window = total_steps / num_windows`.

2. **Finding first/last entries** (lines 298–322): For each window, the code scans the sorted history to find the **first** and **last** entries whose `"step"` falls within that window's range. The first matching entry is stored as `first_entry`, and `last_entry` is overwritten each time (so it ends up being the last matching entry).

3. **Computing per-window displacement** (lines 330–334):
   - `dx = last_entry.com[0] - first_entry.com[0]` (change in x-center-of-mass)
   - `dy = last_entry.com[1] - first_entry.com[1]` (change in y-center-of-mass)
   - `velocity_mag = sqrt(dx² + dy²)` (total distance traveled in the window)

4. **Normalizing by time** (lines 336–343):
   - If `window_steps > 0` (i.e., the first and last entries span actual time steps): divide `velocity_mag`, `dx`, and `dy` by `window_steps` to get a **velocity** (distance per step).
   - If `window_steps == 0` (both entries are on the same step): velocity is set to zero.

5. **Storage** (lines 345–346): Each window's velocity magnitude and (dx, dy) vector are appended to their respective lists for later aggregation.

The key point: **velocity is computed as displacement in the window (from first to last history entry within that window) divided by the step-difference between those two entries**, not by the full window size. This means if entries are sparse in a window, the actual time span used for normalization could be much less than `steps_per_window`.
