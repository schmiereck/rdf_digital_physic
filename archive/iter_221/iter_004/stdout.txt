# Analysis of `src/run_vc_search.py`

## How It Runs

The script performs an **evolutionary (genetic) search** for rules that produce v<c (velocity less than c) gliders in a cellular automaton. Here's the high-level flow:

1. **Argument parsing** via `argparse` — accepts `--output_file` and `--strict` flags.
2. **`run_search(strict)`** is called, which:
   - Creates an output directory (`archive/iter_218/results/`).
   - Initializes a `random.Random(200_001)` RNG.
   - Generates an initial random population of **100 C2-symmetric rules** (128×128 grid, seed: 3-bit L-tromino).
   - Evaluates fitness for all 100 chromosomes.
   - Runs **10 generations** of evolution using:
     - **Top-k selection** (`ELITE_COUNT` = 10% of population = 10 elites).
     - **Two-point crossover** (`crossover_rate=0.8`).
     - **Per-bit mutation** (`mutation_rate=0.01`).
   - Tracks the ever-best champion rule across all generations.
3. **`write_results(result)`** saves three artifacts:
   - `champion_vc_rule.json` — the best rule dict, fitness, and metrics.
   - `evolution_log.csv` — generation-by-generation champion fitness.
   - `champion_vc_glider.gif` — a 200-step animation of the champion.

## Available Fitness Functions

| Fitness Function | How to Select | Description |
|---|---|---|
| **`LeakySubLightFitness`** | **Default** (omit `--strict`) | Uses "leaky" bit-conservation. Rewards displacement with a continuous conservation penalty. Configurable via `checkpoints`, `bits_per_cell`, `velocity_threshold`. |
| **`SubLightFitness`** | Use `--strict` flag | Enforces **strict bit conservation** (`strict_bit_conservation=True`). Bit count must remain exactly equal to the seed bit count (3) at all times, eliminating breeder exploits. Configurable via `window_start/end`, `period_window_start/end`, `max_period`, `v_threshold`, `expected_bits`. |

The switch between them is purely the `--strict` boolean flag passed to `main()`, which routes into the `run_search(strict=True/False)` function.

## Does It Support `--initial_population_path`?

**No, it does not.** The argument parser only defines two flags:

```python
parser.add_argument("--output_file",  ...)  # Override champion output path
parser.add_argument("--strict", action="store_true", ...)  # Use SubLightFitness
```

The initial population is **always** generated on the fly with random C2-symmetric rules:

```python
population = [
    rule_dict_to_chromosome(generate_c2_rule(rng))
    for _ in range(POPULATION_SIZE)
]
```

There is no mechanism to load a pre-existing population from disk. To support that, `main()` would need an `--initial_population_path` argument, and `run_search()` would need logic to load chromosomes from a JSON or similar file and replace the random population initialization.
