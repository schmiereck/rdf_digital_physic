## 3. Population Loading (`load_initial_population`)

The function loads warm-start populations from a JSON file:

### JSON Format Accepted

The file can be either:

1. **A flat JSON list** of rule entries, each with a `"chromosome"` key:
   ```json
   [
     {"chromosome": [0, 1, 0, 1, ...]},     // 128-element binary array
     {"chromosome": [1, 0, 1, 0, ...]},
     ...
   ]
   ```

2. **A dict with a `"population"` key** (also supports `"lookup_table"` as an alias for `"chromosome"`):
   ```json
   {
     "population": [
       {"chromosome": [0, 1, 0, 1, ...]},
       {"lookup_table": [1, 0, 1, 0, ...]},   // alternate key name
     ]
   }
   ```

### Validation

- Each member must have either a `"chromosome"` or `"lookup_table"` key.
- The array must have shape `(128,)` — matching the `LUT_SIZE` constant.
- Values are cast to `np.uint8`.

## 4. Random Population Fallback (`generate_random_population`)

When no `--initial_population_path` is given, a random C2-symmetric population is generated:

1. For each individual, it picks `k ∈ [2, 4]` random `(a, b)` pairs and calls `_try_build_c2_rule(pairs)` to construct a C2-symmetric rule.
2. If C2 symmetry fails, it falls back to a fully random 128-bit chromosome.

## 5. Chromosome Representation

- **128-element binary list/array**: Entry `i` is the new "center" output bit when the local hex neighborhood evaluates to state `i`.
- Converted to a sparse `rule_dict` via `chromosome_to_rule_dict()`, which only stores entries that differ from the identity LUT (default center = `(s >> 6) & 1`).
- **Mutation**: `swap_mutate()` swaps two randomly chosen positions — identical swaps are no-ops, which matches the warm-start construction convention.
