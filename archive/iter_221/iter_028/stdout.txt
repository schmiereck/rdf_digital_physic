   - `_raw_com_and_bits(grid)` computes the **raw (toroidal) CoM** at step 0.
   - `prev_unwrapped` is initialized to this raw CoM, and the first history entry is recorded: `{"step": 0, "com": prev_unwrapped, "bit_count": b0}`.

2. **Loop (steps 1 through STEPS=500):**
   - `step_grid(grid, lut)` advances the CA by one time step.
   - `_raw_com_and_bits(grid)` computes the **raw (toroidal) CoM** (`raw_c`) for the current grid.
   - **Unwrapping happens here:** `_unwrap_com(prev_unwrapped, raw_c)` adjusts `raw_c` relative to the previous raw CoM. If the displacement exceeds half the grid size in either direction, it means a toroidal boundary was crossed, and the coordinate is shifted by ±grid_size.
   - The **unwrapped** CoM is appended to history: `{"step": t, "com": unwrapped, "bit_count": bc}`.
   - `prev_unwrapped` is updated to `raw_c` (the raw position) for the next step's unwrapping calculation.

3. **Where unwrapping is recorded:**
   - The `"com"` field in each history entry stores the **unwrapped** CoM — i.e., absolute, non-wrapping coordinates that grow monotonically as the glider moves across the toroidal boundary.
   - This unwrapped `"com"` is what the downstream `DisplacementConsistencyFitness` reads to measure sustained directional motion, correctly filtering out v=1c (speed-of-light) gliders.

4. **Key insight about `_unwrap_com`:**
   - It takes `prev_unwrapped` (which is actually the **previous raw CoM**, not the previous unwrapped position) and the current `raw_c`, then unwraps the current position.
   - The variable name `prev_unwrapped` is slightly misleading — it tracks the *previous raw* CoM, which serves as the anchor for unwrapping the current step. The returned value is the unwrapped position.
